# Classroom hero service

`ansKeyHeroes` is the authoritative classroom RPG endpoint. Every request verifies a non-revoked Google Firebase ID token, verified email, the existing Ans Key App Check app ID, and the allowed app origin. The teacher realm is resolved from the actual Firebase Auth account for `chungzhikai@gmail.com`; request bodies cannot select ownership or administrator status.

Students claim an existing `students/{id}` register document, not a display name, email guess, or CER UID. A transaction reserves both the roster profile and the account binding. Only the teacher can approve, reject, unlink or run combat. Pending claims can be cancelled by their applicant. Approved claims cannot be taken by another account. Neither claiming nor unlinking changes shared roster/CER identity fields.

Canonical data lives under `classroomHeroData/{teacherUid}/profiles/{studentId}` and `accounts/{uid}`. Browser reads and writes are denied by the shared rules migration in `tools/hero-rules.mjs`. The teacher can still subscribe to `classroomBattles/{teacherUid}/classes/{encodedSlot}`; all battle writes now pass through this service. The migration retains unrelated shared-project rules and validates the old protected/public collection boundaries before publishing with a concurrent-release check.

One canonical profile owns character gender, XP, learned skills across hero classes, inventory, equipment, and the active encounter lock. Register slot changes preserve that profile. Claiming imports one strongest existing saved battle snapshot by XP, then newest update/revision; it never sums duplicated rewards across lessons. Active legacy encounters still hold a lock even if the highest-XP snapshot is already complete. A teacher can end an encounter from Hero claims, including an old lesson slot no longer in the roster, to free the party. Wrong claims can be unlinked without erasing progress.

Battle actions and their immutable receipts commit in the same transaction as every participating hero profile. Shared roster IDs, current slot membership, canonical progression and locks are checked on the server. Clients cannot supply XP, stats, skill points or loot. The deterministic reducer calculates actions/rewards. A repeated action/award ID returns the saved state without repeating damage, consumable use, XP or treasure. Cross-slot battles involving the same hero serialize through the profile lock. Guest wheel entries remain local to their battle rather than becoming claimable register names.

## Request contract

All routes use POST JSON `{type, ...fields}` and the `Authorization: Bearer ...` and `X-Firebase-AppCheck` headers.

| Type | Fields | Result |
|---|---|---|
| `me` | None | `{status, claim?, hero?, activeEncounter?}`; hero includes `classChosen` |
| `catalog` | Optional `lessonSlot` | `{slots:[{id,name}],students:[{id,name,lessonSlots,status}]}` |
| `claim` | `studentId`, `lessonSlot` | Pending self view |
| `cancelClaim` | None | Unclaimed self view |
| `configure` | `command: class/advance/learn/equip/appearance`; `role`/`jobId`/`skillId`/`itemId`/`gender`; optional appearance receipt `id` | Updated owned hero; only cosmetic appearance is allowed during an active encounter |
| `claims` | Teacher only | `{claims,activeEncounters}` including locks on unclaimed profiles |
| `approve`, `reject`, `unlink` | Teacher only, `studentId` | Updated claim status |
| `assist` | Teacher only, `classId`, helper `studentId`, `helpedStudentId`, `action:{id,spinId}` | `{hero,state,assist,mission,duplicate?}` |
| `lessonGuests` | Teacher only, `classId`, `command:get/add/remove`; add/remove need `studentId` and immutable `id` | `{guests:[{studentId,name,lessonSlots}],state,duplicate?}` |
| `mission` | Teacher only, `classId`, `command:get/turn/cancel/focus/incorrect/redeem`; mutations need `id`; Turn needs mission `expectedRevision`; cancel/focus/incorrect need `missionId`; incorrect needs `spinId` and the current question's `expectedRevision`; redeem needs bank `prizeId` | `{mission,state,answer?,balances?,duplicate?}` |
| `endEncounter` | Teacher only, `studentId` | `{state}` or idempotent `{status:'ended'}` |
| `battle` | Teacher only, `classId`, manual `action` (direct `auto` is rejected); summon uses `action:{type:'summon',id,source:'reward'/'teacher',encounterId,expectedRevision}` | `{state,mission}` |
| `wheelAward` | Teacher only, `classId`, `studentId`, positive whole `delta` (1–10000), optional `reason`. Quick fight: `action:{type:'auto',id,spinId,heroId,heroes,bossId,encounterId?,expectedRevision?}`. Ordinary wheel: `mode:'ordinary',action:{type:'award',id,spinId}`. New clients bind both modes with `missionId` (nullable) and `missionRevision` captured for the spin. | `{state?,mission,award:{id,studentId,delta,marks},answer,balances,duplicate?}` |

`configure` may include `studentId` only for the teacher or the student's own approved binding. Optional `expectedRevision` checks the canonical profile version. Class changes preserve skills learned in other classes and current inventory; they do not grant new XP or skill points.

Temporary students are registered students visiting another Lesson slot. Membership lives at `classroomHeroData/{teacherUid}/lessonGuests/{encodedSlot}` independently of the permanent `students.slot`/`students.slots` fields, and stays until the teacher removes the guest. The teacher-only `lessonGuests` route is shared by the wheel and manual battle. Add validates a real target with registered students, a registered student from another slot, the 100-hero limit and the canonical cross-lesson encounter lock. Get returns fresh roster names/source slots and prunes missing or now-permanent entries. Deleted or slotless guests are also removed from the active party and their matching locks released; a selected pending guest requires resolving or skipping first, with no partial cleanup. Guests who become permanent retain their active hero and lock. Removal remains available even if the target's permanent roster disappears.

Guest add/remove mutations and immutable receipts are transactional. Retrying an older add after removal, or an older removal after re-addition, returns current membership without replaying the old change. Joining an active encounter inserts the canonical hero and lock atomically without changing enemy HP, pending answers, combat history or granting rewards. Removing the selected pending hero is rejected until the teacher resolves or skips the answer; removing another guest preserves the pending answer and releases only that guest's matching lock. Completed encounters stay historical. Guests use their existing claim, XP, skills, equipment and inventory; marks, assist XP, victory treasure and class mission bonuses write to the same registered student and canonical hero. Class payouts include the union of permanent members and current valid guests exactly once. No shared Firestore rules change is needed; deploy `ansKeyHeroes` before this frontend release.

Quick wheel spins only select a student. `wheelAward` derives combat power from `delta` and commits marks, the standard `awards` history (Firestore timestamp), active school-wide boss point damage, battle state, all canonical profiles and the receipt atomically. Its unique award ID is separate from the saved spin ID. Reusing a receipt with different student/points/spin/reason is rejected; an identical retry returns the latest battle and current marks without repeating the award. A failed or stale transaction writes nothing. The client keeps uncertain requests in session storage and offers Retry. Deploy the updated endpoint before the v1.118 frontend; no additional shared-rules migration is required for this change.

With Quick fight off, `wheelAward` takes a separate ordinary transaction that never reads or writes encounter or profile documents and never invokes the combat reducer. It saves marks, normal award history, existing school-wide boss point damage, the mission answer, any class-points prize and the immutable award receipt together. Receipt subdocuments remain under the class's existing `actions` collection without creating a class encounter document. Each new award ID can award more points on the same spin; the shared mission/question receipt counts the question only once. The ordinary receipt binds mode, student, points, reason, spin and the captured mission identity/revision. A question from before a mission roll or a previous mission can still receive points but cannot advance the newer mission. Existing Quick fight receipts without the new fields remain retryable.

Wheel and manual incorrect answers record `current.lastResetRevision`. A delayed new-format correct award captured before that reset still saves its legitimate points, but cannot restart or extend the newer streak. Distinct current questions from concurrent tabs can count independently; mission revision is an ordering guard for resets, not a blanket lock that discards legitimate concurrent point awards.

`assist` is teacher-only: `{classId,studentId,helpedStudentId,action:{id,spinId}}`. It returns `{hero,state,assist,duplicate?}` and always grants 6 XP, ignoring client XP amounts. Both students must belong to the Lesson slot and must differ. A hash of spin ID and helper ID identifies the immutable receipt under the class’s `assists` collection, so a fresh action ID cannot repeat the same helper/question bonus. The canonical profile and an existing encounter’s helper snapshot update atomically without a battle action, marks, enemy response or resource costs. An absent encounter stays absent. Cross-lesson active locks still apply.

Advanced jobs live in `hero.job` while `hero.role` retains the base class. `configure` with `command:'advance',jobId` checks earned level 15, the matching base class, ownership and encounter locks. The eight job trees and their bonuses are canonical game content. Inactive job skills cannot be cast or provide passive bonuses. Loot equips the highest-rarity equipment deterministically after granting rewards; ties retain current equipment, and equipping alone cannot heal or refill mana. Enemy state gains `bossMp`/`bossMaxMp`; legacy states normalize to 60 MP, ultimate skills spend 30, normal attacks restore 15. Saved support effects include actual recipient IDs and amounts for shields, mana, cleanse and haste, plus poison/weaken records; animations never infer or mutate combat rewards.

`hero.gender` is `male` or `female`, defaulting legacy heroes to `male`. `configure` with `command:'appearance',gender` requires the approved owner or teacher and rejects invalid values. It updates the canonical hero and the actual locked active encounter together, including a moved lesson’s encounter, without altering combat resources, pending answers, events or progress. Student responses contain only their own hero. Optional immutable appearance receipts prevent delayed or concurrent retries from undoing newer choices. The teacher battle journal uses `sync:appearance` with existing action receipts; it is allowed during pending answers, and preserves the last animation event so a cosmetic edit cannot replay a saved fight. Client lifecycle guards prevent a delayed token check from sending after close, account change or lesson switch.

## Build and deployment

Class missions are stored separately from encounters at `classroomHeroData/{teacherUid}/missions/{encodedSlot}`. They can be rolled before combat and survive new encounters. `mission:get` is the authenticated teacher read; browsers cannot write this namespace. `mission-content.js` owns four objectives and eight prizes. A server cryptographic roll selects each objective with 25% probability, each of the six minute prizes with 15%, and the summon/+5-points prizes with 5% each. The roll is sampled once outside transaction retries. Immutable action receipts and revision checks prevent refreshes or racing clicks from rerolling an active mission; the teacher must explicitly cancel first.

Correct-answer streaks advance only from saved manual correct answers or atomic wheel awards in either mode. An additional receipt keyed by mission and question prevents multiple point buttons on the same spin from counting as multiple answers. Manual Incorrect and the wheel's teacher-only `mission:incorrect` reset the streak; incorrect receipts are keyed by mission/spin. Wheel resets first return any committed receipt, then require the question's captured mission revision to equal the current mission revision. Thus a saved reset remains safe to retry after a lost response, and an uncommitted old reset cannot erase newer progress. Reset writes the shared question receipt as incorrect, preventing subsequent points on that question from recounting it. Correct answers return `answer:{spinId,missionId,revision,outcome}`; duplicates and extra awards retain the original question revision. The current answer can be corrected immediately using its acknowledged revision, but a mission refresh must never rebind an older question to a newer revision. Assist progress comes only from new canonical assist receipts. The focus objective requires 30 elapsed server-clock minutes and an explicit teacher `focus` confirmation; client timestamps cannot complete it. The next-enemy objective binds the active encounter, or the next started encounter, and completes only on a new victory. An explicitly abandoned encounter allows the following encounter to become the target.

Completed prizes enter the class bank. Blooket/Gimkit minute prizes are teacher-redeemed records; this service does not call either game. Summon rewards are consumed atomically with a saved `summon` battle action; the teacher also has a free `source:'teacher'` help action. One Huge Punch deals exactly the remaining enemy HP, bypasses guard, clears a pending answer and grants the normal once-only victory treasure to every encounter hero. Cross-lesson locks, revisions and teacher authentication still apply. A failed or duplicate transaction cannot spend another token or award another chest.

The class-points prize immediately adds exactly 5 marks and an ordinary awards-ledger row to each current roster member and valid temporary guest of that Lesson slot. This happens in the same completion transaction, without another combat turn or school-boss attack. A simultaneous wheel award adds both values and returns the final `award.marks`. `mission.lastPayout.awards` is a historical snapshot; new wheel and mission mutation responses provide canonical `balances:[{studentId,marks}]`, including duplicates, so replaying a completion cannot replace newer displayed marks with the old payout. All unredeemed prizes are retained; redeemed history is bounded, and a full bank of 200 available prizes must be redeemed before another roll.

The ordinary-wheel mission fix requires deploying only `functions:ans-key-live:ansKeyHeroes` to `mathgen--app` before its frontend release. No shared Firestore rules change or data migration is required.

Saved battle state contains the latest 40 `combatLog` rows across encounters. Rows store names with actual damage, healing, support, shields absorbed, enemy healing and poison damage. Automatic turns produce one row with a nested saved enemy reply, never duplicate intermediate reducer phases. Selection, roster sync and cosmetic edits do not create combat entries. Presentation reads these records and cannot write outcomes. No additional Firestore rules migration is needed for missions; deploy the updated endpoint and shared game bundle before the frontend.

Run `node tools/sync-hero-game.mjs` after editing browser battle rules. The checked-in `functions/hero-game` copy is needed because Firebase uploads only the functions source directory. Tests verify byte parity. Run `npm --prefix functions test`, `node --test tools/hero-api-tests.mjs tools/hero-rules-tests.mjs`, and the existing battle checks before deployment.

Deploy `ansKeyHeroes` and apply `tools/hero-rules.mjs` against the current shared rules before publishing the frontend release. The Firebase service account must retain normal Admin Firestore and Firebase Auth user lookup access. No new secrets are needed. Do not deploy an app-local replacement Firestore rules file. Old browser battle writers are intentionally rejected after the authoritative rules upgrade; users refresh Ans Key to use the new server route.
